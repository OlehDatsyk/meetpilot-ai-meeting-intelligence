# Security

## Reporting a vulnerability

Please do not open a public issue. Use **Report a vulnerability** under this repository's Security tab if it is available, or contact the maintainer privately through their GitHub profile. Include steps to reproduce and the affected version. This is a portfolio project maintained by one person, so there is no guaranteed response time.

## Authentication

- Passwords: Argon2id (argon2-cffi), at least 10 characters. Unknown emails take the same time and return the same error as wrong passwords.
- Sessions: HS256 JWT bearer tokens signed with `SECRET_KEY`, lasting `ACCESS_TOKEN_MINUTES` (default 12 hours). Each user has a token version. Signing out, changing the password, and resetting it increment the version, which revokes every earlier token.
- Production refuses to start without a `SECRET_KEY` of at least 32 characters. In development a temporary random key is used, with a warning.
- Password reset: random 32-byte tokens, stored only as SHA-256 hashes, single use, 30-minute expiry. The request endpoint always returns the same message, so it does not reveal accounts.
- Tokens are kept in the browser's `localStorage`. This avoids cross-site cookie problems between separate frontend and API hosts, but it means a cross-site scripting bug could read the token. The mitigations are React's escaping, no use of `dangerouslySetInnerHTML`, and a strict Content-Security-Policy on the static site.

## Authorisation

Every endpoint goes through `deps.py`: the user must be a member of the record's workspace (otherwise **404**) with a sufficient role (otherwise **403**). This is enforced on the server whatever the UI shows. Automated tests check that a second user gets 404 on another user's meetings, transcripts, summaries, recordings, playback links, reports, exports, jobs, segments, action items, search and assistant data, and that viewers cannot write.

## Upload validation

The extension is allow-listed, and the content must match a known audio container by its first bytes and match the extension. The file must parse with mutagen and have a positive duration. Size is enforced while streaming (and from `Content-Length`), and duration after parsing. Original file names are reduced to a base name and never used as storage paths. Storage keys are generated by the server and validated against path traversal. Audio is decoded by ffmpeg in a subprocess with timeouts.

## Secrets

- Never committed: `.gitignore` excludes `.env`, `.env.*` (except `.env.example`), databases, storage, models, audio, logs and virtual environments.
- Provider keys are server-side only. `/system/status` reports which providers are configured, never their keys (tested). The frontend's only build variable is `VITE_API_BASE_URL`.
- Render generates `SECRET_KEY` (`generateValue: true`); other secrets use `sync: false`, so they are entered in the dashboard.

## Storage

Private by default: local files are served only through authorised endpoints, and S3 objects only through 15-minute pre-signed URLs. Use a private bucket with public access blocked. Downloaded HTML reports are sent as attachments with `Content-Security-Policy: sandbox`, so they cannot run script on the API origin.

## API protection

- CORS: only the origins in `CORS_ORIGINS`, no credentials mode, fixed methods and headers. Production configuration was checked: an unknown origin's preflight is rejected.
- Rate limits per client IP for sign-up, sign-in, password reset, uploads, analysis, reports, the assistant and search. Behind Render's proxy only the right-most `X-Forwarded-For` entry is trusted. Limits are per process (documented limitation).
- Security headers: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, and HSTS in production. API responses are `Cache-Control: no-store`. The static site adds a strict CSP.
- Errors: a consistent JSON shape. Unhandled exceptions return a generic 500. Provider payloads are never forwarded.
- SQL: SQLAlchemy parameters throughout. LIKE wildcards in search input are escaped.
- CSV exports neutralise spreadsheet formulas. Jinja2 autoescapes report HTML (tested with a `<script>` title).
- `/docs` and `/openapi.json` are disabled in production.

## Logging

Logs contain request methods and paths, job IDs and error types. They never contain transcript text, audio, prompts, AI output or keys. Third-party HTTP loggers (`httpx`, `httpx2`, `openai`, `anthropic`, `botocore` and others) are held at WARNING. The one exception is local development without SMTP: the password-reset link is printed to the API console, so it can be tested.

## Dependencies

Versions are pinned (`backend/requirements*.txt`, `frontend/package-lock.json`). On 2026-11-11, `npm audit` reported 0 vulnerabilities (after vitest was upgraded to 5.1.0 to fix a critical advisory in older tinypool), and `pip-audit` reported no known vulnerabilities in `requirements-local.txt` and `requirements-dev.txt`.

## Known limitations

- No multi-factor authentication or account lockout. Rate limits slow guessing only.
- Rate limits are in memory and reset on restart.
- Tokens in `localStorage` (see above).
- Members can be added only by an email that already has an account. This shows admins whether an email is registered.
- The embedded worker shares CPU and memory with the API. On small instances, long transcriptions slow down requests.
